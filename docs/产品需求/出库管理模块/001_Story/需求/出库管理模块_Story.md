**结论：销售出库是核心，调拨出库次之，其他类型可简化处理。**

## 二、订单接收场景分析

### 2.1 多平台订单涌入

**实际痛点：**
```
早上打开系统：
- Shopee同步了150单（格式A）
- Lazada同步了80单（格式B）
- TikTok同步了40单（格式C）
- 客服手工录入了10单（特殊订单）

问题：
1. 各平台SKU编码可能不统一
2. 订单优先级不同（Shopee要求24h发货）
3. 部分订单需要合并（同一客户多单）
4. 部分订单地址异常需要人工处理
```

**需求分析：**

| 功能需求 | 场景支持 | 优先级 |
|---------|---------|--------|
| 统一订单接收 | 多平台订单自动同步 | P0 |
| 订单格式转换 | 各平台格式统一化 | P0 |
| SKU映射 | 平台SKU与系统SKU对应 | P0 |
| 订单校验 | 地址、库存、价格校验 | P0 |
| 异常标记 | 问题订单人工处理 | P1 |

## 三、波次管理场景分析

### 3.1 波次的必要性

**不使用波次的问题：**
```
200个订单，200个拣货任务
→ 拣货员来回跑200次
→ 同一个库位可能被访问50次
→ 效率极低
```

**使用波次优化：**
```
200个订单，按区域合并成5个波次
→ 每个波次只访问相关库位
→ 同库位商品一次取完
→ 效率提升3-5倍
```

### 3.2 波次策略场景

| 策略 | 实际场景 | 效果 |
|------|---------|------|
| **按时间** | 10点前的订单一起处理 | 批量化，减少切换 |
| **按物流** | J&T的订单一起处理 | 快递分拣效率提升 |
| **按区域** | 雅加达地区的订单一起 | 配送路线优化 |
| **按商品** | 含相同SKU的订单一起 | 减少拣货次数 |
| **按客户** | 同一客户多单合并 | 减少包裹数 |

### 4.2 拣货策略对比

| 策略 | 操作方式 | 适用场景 | 优缺点 |
|------|---------|---------|--------|
| **摘果式** | 按订单逐个拣 | 订单少、商品多 | 准确率高，但行走距离长 |
| **播种式** | 先批量拣再分播 | 订单多、商品集中 | 效率高，需要二次分拣 |
| **边拣边分** | 拣货时直接分到订单箱 | 中等规模 | 效率平衡，操作复杂 |

### 4.3 播种式拣货详解（电商常用）

**第一步：批量拣货**
```
- 波次W001需要SKU-009共50件
- 拣货员到A-R01-L01一次取50件
- 推车到播种区
```

**第二步：分播分配**
```
┌─────────────────────────────────────────┐
│ 播种墙（订单箱格子）                     │
├─────────────────────────────────────────┤
│ ┌───┬───┬───┬───┬───┬───┬───┬───┐      │
│ │01 │02 │03 │04 │05 │06 │07 │08 │...   │
│ │4件│2件│3件│1件│5件│2件│4件│3件│      │
│ └───┴───┴───┴───┴───┴───┴───┴───┘      │
│                                         │
│ PDA扫描SKU-009，系统提示分配方案         │
│ 分播员按方案放入各箱子                   │
└─────────────────────────────────────────┘
```

**第三步：封箱**
```
- 每个箱子分配完毕，直接封箱
- 分播过程 = 复核过程
```

### 4.4 拣货路径优化

**路径策略：**

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| S型路径 | 蛇形穿梭，不走回头路 | 单巷道仓库 |
| Z型路径 | 来回穿梭 | 多巷道仓库 |
| 最近优先 | 按距离排序 | 拣货点分散 |

**MVP简化算法：**
```
1. 按库区分组（收货区→存储区→拣货区）
2. 同库区内按巷道排序
3. 巷道内按层排序（从上到下或从下到上）
```

## 五、复核打包场景分析

### 5.1 复核的必要性

**拣货可能出错的原因：**
```
1. 商品外观相似，拿错
2. 条码相似，扫错
3. 数量点错
4. 订单对应错误

后果：
- 客户投诉
- 退货成本（跨境退货更贵）
- 差评影响店铺评分
```

### 5.2 复核方式选择

| 场景 | 复核方式 | 操作说明 |
|------|---------|---------|
| **小单（<5件）** | 边拣边核 | 拣货时PDA已确认，无需二次核 |
| **中单（5-20件）** | 抽检+称重 | 随机抽3件，称重校验 |
| **大单（>20件）** | 播种分拣 | 分播过程即复核 |
| **贵重品（>500元）** | 逐件核 | 每件扫码确认 |

### 5.3 称重复核原理

```
┌─────────────────────────────────────────┐
│ 打包复核界面                             │
├─────────────────────────────────────────┤
│ 订单号：SO20260531001                   │
│ 商品明细：                              │
│   SKU-009 海飞丝洗发水 ×2 = 200g       │
│   SKU-010 玉兰油面霜 ×1 = 250g         │
│   包材：纸箱150g                        │
│ ────────────────────                    │
│ 理论重量：600g                          │
│                                         │
│ [连接电子秤]                            │
│ 实际重量：___g                          │
│                                         │
│ 误差范围：±5%（±30g）                   │
│ [通过] [异常]                           │
└─────────────────────────────────────────┘

系统计算公式：
订单重量 = Σ(SKU重量 × 数量) + 包材重量
```

### 5.4 打包决策

```
打包时需要决定：
1. 包装箱型：根据商品尺寸重量推荐
2. 是否分箱：商品过多或体积过大
3. 是否合包：同一客户多单合并
4. 物流选择：根据目的地自动匹配
```

## 七、异常处理场景分析

### 7.1 常见异常及处理

| 异常类型 | 发生频率 | 原因 | 处理方式 |
|---------|---------|------|---------|
| **缺货** | 5% | 库存数据不准 | 标记缺货→触发补货→部分发货 |

| **拣货错误** | 0.5% | 拣错商品 | 重新拣货→更新库存 |

## 十、核心业务规则

### 10.1 状态流转规则

```
出库单状态流转：

待分配(0)
    │ 波次分配
    ▼
已分配(1)
    │ 开始拣货
    ▼
拣货中(2)
    │ 拣货完成
    ▼
待打包(3)
    │ 打包完成
    ▼
待发货(4)
    │ 发货确认
    ▼
已发货(5)

异常分支：
待分配 → 已取消(9)
拣货中 → 缺货处理 → 部分发货
```

### 10.2 库存锁定规则

| 时间点 | 库存操作 |
|--------|---------|
| 创建出库单 | 不锁定（只检查是否充足） |
| 波次释放 | 锁定库存(qty_locked增加) |
| 拣货确认 | 不变（已锁定） |
| 发货确认 | 扣减库存(qty_total减少，qty_locked减少) |
| 取消订单 | 释放锁定(qty_locked减少) |

### 10.3 数据一致性规则

```
库存数量关系：
qty_total = qty_available + qty_locked

约束条件：
1. 发货数量 ≤ 拣货数量 ≤ 锁定数量
2. 库存扣减必须在发货确认时
3. 波次取消必须释放锁定
4. 部分发货时调整锁定数量
```
