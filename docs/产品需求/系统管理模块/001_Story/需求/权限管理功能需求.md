# 用户管理功能需求

> 模块说明: 系统用户管理（含角色分配、仓库权限）
> 优先级: P1
> 创建时间: 2026-06-07

---

## 一、业务背景

### 1.1 当前问题

- 用户只能分配单一角色，无法身兼多职
- 用户只能绑定单一仓库，无法操作多个仓库
- 员工信息字段不完整，缺少工号、部门、岗位等业务字段
- 缺少枚举值约束，用户输入数据不规范

### 1.2 业务场景

```
┌─────────────────────────────────────────────────────────────┐
│                    WMS 员工管理场景                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 一人多岗                                                │
│     - 小仓库：一人兼任收货员+上架员+盘点员                   │
│     - 临时支援：拣货员帮忙打包                               │
│                                                             │
│  2. 多仓库操作                                              │
│     - 主管管理多个仓库                                       │
│     - 调拨需要双方仓库权限                                   │
│                                                             │
│  3. 员工生命周期                                            │
│     - 入职 → 分配角色/仓库 → 在职工作 → 离职                 │
│                                                             │
│  4. 权限控制                                                │
│     - 按岗位分配角色 → 自动获得操作权限                      │
│     - 按仓库控制数据范围                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 设计原则

**角色固定，权限跟着角色走**：

- 系统预置角色（拣货员、打包员、收货员等）
- 每个角色有固定的权限集合
- 用户分配角色后自动获得对应权限
- 不需要单独的权限配置功能

## 二、数据模型设计

### 2.1 员工表字段扩展

| 字段 | 类型 | 必填 | 说明 | 枚举约束 |
|-----|------|-----|------|---------|
| `id` | BIGINT | 是 | 主键ID | - |
| `username` | VARCHAR(50) | 是 | 登录账号 | - |
| `password` | VARCHAR(255) | 是 | 密码（加密） | - |
| `employee_no` | VARCHAR(20) | 是 | 员工工号 | - |
| `name` | VARCHAR(100) | 是 | 姓名 | - |
| `phone` | VARCHAR(20) | 否 | 手机号 | - |
| `email` | VARCHAR(100) | 否 | 邮箱 | - |
| `department` | INT | 是 | 所属部门 | 字典：department |
| `position` | INT | 是 | 岗位名称 | 字典：position |
| `hire_date` | DATE | 否 | 入职日期 | - |
| `work_status` | INT | 是 | 工作状态 | 字典：work_status |
| `skill_level` | INT | 否 | 技能等级 | 字典：skill_level |
| `shift_type` | INT | 否 | 班次类型 | 字典：shift_type |
| `status` | INT | 是 | 账号状态 | 0禁用 1启用 |
| `warehouse_ids` | 关联表 | 是 | 可操作仓库 | - |

**移除字段**：
- `role_id` → 改为关联表 `sys_user_role`

**新增关联表**：
- `sys_user_role` - 用户角色关联（多角色）
- `sys_user_warehouse` - 用户仓库关联（多仓库）

---

### 2.2 枚举值定义

#### 部门 (department)

| 编码 | 名称 | 说明 |
|-----|------|------|
| 1 | 入库组 | 收货员、质检员、上架员 |
| 2 | 出库组 | 拣货员、打包员、发货员 |
| 3 | 库存组 | 盘点员、库存管理员 |
| 4 | 管理组 | 仓库主管、系统管理员 |

> 注：WMS 是仓库内部系统，部门按功能组划分，不需要公司级别的部门分类

#### 岗位 (position)

| 编码 | 名称 | 对应角色 | 说明 |
|-----|------|---------|------|
| 1 | 拣货员 | PICKER | 负责拣货作业 |
| 2 | 打包员 | PACKER | 负责打包作业 |
| 3 | 发货员 | SHIPPER | 负责发货作业 |
| 4 | 收货员 | RECEIVER | 负责收货作业 |
| 5 | 质检员 | INSPECTOR | 负责验收作业 |
| 6 | 上架员 | PUTAWAY_CLERK | 负责上架作业 |
| 7 | 盘点员 | STOCKTAKER | 负责盘点作业 |
| 8 | 仓库主管 | WAREHOUSE_MANAGER | 管理审批 |
| 9 | 系统管理员 | SYSTEM_ADMIN | 系统配置 |

#### 工作状态 (work_status)

| 编码 | 名称 | 说明 | 账号状态 |
|-----|------|------|---------|
| 1 | 在职 | 正常工作 | 启用 |
| 2 | 休假 | 临时请假，暂停分配任务 | 启用 |
| 3 | 离职 | 已离职 | 禁用 |

#### 技能等级 (skill_level)

| 编码 | 名称 | 说明 |
|-----|------|------|
| 1 | 初级 | 新员工，需要指导 |
| 2 | 中级 | 独立操作 |
| 3 | 高级 | 熟练工，可带新人 |
| 4 | 专家 | 可处理复杂情况、培训他人 |

#### 班次类型 (shift_type)

| 编码 | 名称 | 工作时段示例 |
|-----|------|-------------|
| 1 | 早班 | 08:00-17:00 |
| 2 | 中班 | 14:00-23:00 |
| 3 | 晚班 | 22:00-07:00 |
| 4 | 常白班 | 行政岗位，固定白班 |

### 2.4 权限编码规则

```
格式：模块:子模块:操作

示例：
- inbound:receive:view      # 查看收货任务
- inbound:receive:operate   # 收货操作
- outbound:pick:view        # 查看拣货任务
- outbound:pick:operate     # 拣货操作
- system:user:view          # 查看用户
- system:user:create        # 创建用户
```

## 三、功能需求

### Story 1: 用户列表

**作为** 系统管理员
**我希望** 查看所有员工列表
**以便** 管理员工信息和权限

**验收标准:**
- [ ] 显示员工列表：工号、姓名、部门、岗位、工作状态、账号状态
- [ ] 支持按部门筛选
- [ ] 支持按工作状态筛选（在职/休假/离职）
- [ ] 支持按姓名/工号搜索
- [ ] 点击员工可查看详情

---

### Story 2: 创建员工

**作为** 系统管理员
**我希望** 创建新员工账号
**以便** 让新员工能够使用系统

**验收标准:**
- [ ] 输入员工工号（唯一性校验）
- [ ] 输入姓名、手机号、邮箱
- [ ] 选择部门（下拉选择，枚举约束）
- [ ] 选择岗位（下拉选择，枚举约束）
- [ ] 选择工作状态（默认在职）
- [ ] 选择技能等级（可选）
- [ ] 选择班次类型（可选）
- [ ] 选择入职日期（可选）
- [ ] 分配角色（多选）
- [ ] 分配仓库（多选）
- [ ] 自动生成登录账号（工号）
- [ ] 设置初始密码

---

### Story 3: 编辑员工

**作为** 系统管理员
**我希望** 编辑员工信息
**以便** 更新员工状态或调整权限

**验收标准:**
- [ ] 修改姓名、手机号、邮箱
- [ ] 修改部门、岗位（下拉选择）
- [ ] 修改工作状态（在职→休假→离职）
- [ ] 修改技能等级、班次类型
- [ ] 调整角色分配（多选）
- [ ] 调整仓库权限（多选）
- [ ] 离职时自动禁用账号

---

### Story 4: 员工详情

**作为** 系统管理员
**我希望** 查看员工完整信息
**以便** 了解员工权限和工作情况

**验收标准:**
- [ ] 显示基本信息：工号、姓名、部门、岗位
- [ ] 显示工作信息：工作状态、技能等级、班次、入职日期
- [ ] 显示分配的角色列表
- [ ] 显示可操作的仓库列表
- [ ] 显示登录信息：最后登录时间、登录次数
- [ ] 显示操作日志（修改记录）

---

### Story 5: 启用/禁用账号

**作为** 系统管理员
**我希望** 启用或禁用员工账号
**以便** 控制员工是否可以登录系统

**验收标准:**
- [ ] 禁用账号后员工无法登录
- [ ] 启用账号后员工可以正常登录
- [ ] 离职员工自动禁用账号
- [ ] 操作需要确认提示

---

### Story 6: 重置密码

**作为** 系统管理员
**我希望** 重置员工密码
**以便** 帮助忘记密码的员工

**验收标准:**
- [ ] 重置为默认密码或随机密码
- [ ] 记录密码重置时间
- [ ] 通知员工新密码（邮件/短信）

---

### Story 7: 字典管理

**作为** 系统管理员
**我希望** 查看系统枚举字典
**以便** 了解系统预置的选项值

**验收标准:**
- [ ] 查看字典列表（按类型分组）
- [ ] 显示部门、岗位、工作状态、技能等级、班次等字典
- [ ] 预置字典不可修改（权限固定）

> 注：预置角色和权限是固定的，不需要动态配置。如需调整权限，需由开发人员修改代码。

---

### Story 8: 权限校验

**作为** 系统
**我希望** 在操作时校验用户权限
**以便** 确保用户只能执行有权限的操作

**验收标准:**
- [ ] 后端接口校验用户是否有对应权限
- [ ] 无权限时返回 403 错误
- [ ] 前端菜单根据权限过滤显示
- [ ] 前端按钮根据权限显示或隐藏
- [ ] 数据查询按仓库权限过滤

---

### Story 9: 数据权限

**作为** 系统
**我希望** 按仓库过滤用户可见数据
**以便** 用户只能看到自己权限范围内的数据

**验收标准:**
- [ ] 用户只能查看分配仓库的数据
- [ ] 系统管理员可查看全部数据
- [ ] 仓库主管可查看管理仓库的数据
- [ ] 查询时自动添加仓库过滤条件

## 五、数据库设计

### 5.1 员工表

```sql
CREATE TABLE sys_user (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    username        VARCHAR(50) NOT NULL UNIQUE COMMENT '登录账号',
    password        VARCHAR(255) NOT NULL COMMENT '密码',
    employee_no     VARCHAR(20) NOT NULL UNIQUE COMMENT '员工工号',
    name            VARCHAR(100) NOT NULL COMMENT '姓名',
    phone           VARCHAR(20) COMMENT '手机号',
    email           VARCHAR(100) COMMENT '邮箱',
    department      INT NOT NULL COMMENT '部门（字典）',
    position        INT NOT NULL COMMENT '岗位（字典）',
    hire_date       DATE COMMENT '入职日期',
    work_status     INT NOT NULL DEFAULT 1 COMMENT '工作状态（字典）',
    skill_level     INT COMMENT '技能等级（字典）',
    shift_type      INT COMMENT '班次类型（字典）',
    status          INT NOT NULL DEFAULT 1 COMMENT '账号状态: 0禁用 1启用',
    last_login_time DATETIME COMMENT '最后登录时间',
    last_login_ip   VARCHAR(50) COMMENT '最后登录IP',
    login_count     INT DEFAULT 0 COMMENT '登录次数',
    create_user     BIGINT COMMENT '创建人',
    create_time     DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_user     BIGINT COMMENT '更新人',
    update_time     DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_employee_no (employee_no),
    INDEX idx_department (department),
    INDEX idx_work_status (work_status)
) COMMENT '员工表';
```

### 5.2 用户角色关联表

```sql
CREATE TABLE sys_user_role (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT NOT NULL COMMENT '用户ID',
    role_id     BIGINT NOT NULL COMMENT '角色ID',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_role (user_id, role_id),
    INDEX idx_user_id (user_id),
    INDEX idx_role_id (role_id)
) COMMENT '用户角色关联表';
```

### 5.3 用户仓库关联表

```sql
CREATE TABLE sys_user_warehouse (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT NOT NULL COMMENT '用户ID',
    warehouse_id    BIGINT NOT NULL COMMENT '仓库ID',
    permission_type INT DEFAULT 1 COMMENT '权限类型: 1可操作 2仅查看',
    create_time     DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_warehouse (user_id, warehouse_id),
    INDEX idx_user_id (user_id),
    INDEX idx_warehouse_id (warehouse_id)
) COMMENT '用户仓库关联表';
```

### 5.4 系统字典表

```sql
CREATE TABLE sys_dict (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    dict_type   VARCHAR(50) NOT NULL COMMENT '字典类型',
    dict_code   INT NOT NULL COMMENT '字典编码',
    dict_value  VARCHAR(100) NOT NULL COMMENT '字典值',
    sort_order  INT DEFAULT 0 COMMENT '排序',
    status      INT DEFAULT 1 COMMENT '状态: 0禁用 1启用',
    is_system   INT DEFAULT 0 COMMENT '是否预置: 0否 1是',
    remark      VARCHAR(200) COMMENT '备注',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_type_code (dict_type, dict_code),
    INDEX idx_dict_type (dict_type)
) COMMENT '系统字典表';
```
