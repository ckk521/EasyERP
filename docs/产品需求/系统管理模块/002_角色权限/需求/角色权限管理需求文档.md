# 角色权限管理模块需求文档

> 模块说明: 角色管理、权限配置、用户角色分配
> 优先级: P0 (MVP必需)
> 创建时间: 2026-06-10
> 更新时间: 2026-06-10

---

## 一、需求分析

### 1.1 当前问题

通过分析现有代码和数据库设计，发现以下问题：

| 问题 | 现状 | 影响 |
|-----|------|------|
| **权限数据不完整** | `sys_permission` 表只有结构定义，没有初始化数据 | 权限校验无法生效 |
| **角色权限未配置** | `sys_role_permission` 表关联的是不存在的权限 | 角色无实际权限 |
| **权限编码不规范** | 缺少统一的权限编码规范 | 难以维护和扩展 |
| **权限范围模糊** | 未区分菜单权限、按钮权限、数据权限 | 权限粒度不够 |
| **缺少权限管理界面** | 没有角色权限配置的前端页面 | 无法动态调整权限 |

### 1.2 现有数据库结构

**已有表结构：**

```
sys_user          - 用户/员工表（已完成）
sys_role          - 角色表（已创建，缺少数据）
sys_permission    - 权限表（已创建，缺少数据）
sys_role_permission - 角色权限关联表（已创建，数据无效）
sys_user_role     - 用户角色关联表（已创建）
sys_user_warehouse - 用户仓库关联表（已创建）
sys_dict          - 系统字典表（已初始化）
```

**已有角色（9个预置角色）：**

| 角色编码 | 角色名称 | 说明 |
|---------|---------|------|
| PICKER | 拣货员 | 出库拣货作业 |
| PACKER | 打包员 | 出库打包作业 |
| SHIPPER | 发货员 | 出库发货作业 |
| RECEIVER | 收货员 | 入库收货作业 |
| INSPECTOR | 质检员 | 入库验收作业 |
| PUTAWAY_CLERK | 上架员 | 入库上架作业 |
| STOCKTAKER | 盘点员 | 库存盘点作业 |
| WAREHOUSE_MANAGER | 仓库主管 | 管理审批 |
| SYSTEM_ADMIN | 系统管理员 | 系统配置 |

### 1.3 业务场景

```
┌─────────────────────────────────────────────────────────────┐
│                   角色权限管理场景                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 角色分配场景                                            │
│     - 新员工入职 → 分配角色 → 自动获得对应权限              │
│     - 员工转岗 → 调整角色 → 权限自动更新                    │
│     - 临时授权 → 多角色 → 权限叠加                          │
│                                                             │
│  2. 权限校验场景                                            │
│     - 访问菜单 → 校验菜单权限 → 显示/隐藏                   │
│     - 点击按钮 → 校验操作权限 → 启用/禁用                   │
│     - 查询数据 → 校验数据权限 → 过滤范围                    │
│                                                             │
│  3. 权限管理场景（Phase 2）                                 │
│     - 创建新角色 → 配置权限 → 分配给用户                    │
│     - 调整权限 → 角色权限变更 → 即时生效                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.4 设计原则

**MVP 阶段：角色固定，权限跟着角色走**

- ✅ 系统预置 9 个角色，角色固定不可修改
- ✅ 每个角色有固定的权限集合，权限编码硬编码在数据库
- ✅ 用户分配角色后自动获得对应权限
- ❌ MVP 不支持自定义创建角色（Phase 2 支持）
- ❌ MVP 不支持动态调整权限（需开发人员修改 SQL）

**Phase 2：支持自定义角色**

- 支持创建自定义角色
- 支持动态配置角色权限
- 支持角色复制和模板

## 二、权限体系设计

### 2.1 权限类型

| 权限类型 | type值 | 说明 | 示例 |
|---------|--------|------|------|
| **菜单权限** | `menu` | 控制菜单是否显示 | `inbound:menu` 入库管理菜单 |
| **操作权限** | `operation` | 控制按钮是否可用 | `inbound:order:create` 创建入库单 |

**注意：** 数据权限不存储在权限表中，而是通过角色的 `data_scope` 字段控制。

### 2.2 权限编码规范

**格式：`{模块}:{子模块}:{操作}`**

```
模块编码规范：
- system    - 系统管理
- inbound   - 入库管理
- outbound  - 出库管理
- inventory - 库存管理
- return    - 退换货管理
- report    - 报表分析
- dashboard - 仪表盘

操作编码规范：
- view      - 查看权限（列表页、详情页）
- create    - 创建权限
- edit      - 编辑权限
- delete    - 删除权限
- approve   - 审核权限
- export    - 导出权限
- operate   - 操作权限（作业类操作）
```

**示例：**

```
入库管理模块权限：
- inbound:order:view      查看入库单列表和详情
- inbound:order:create    创建入库单
- inbound:order:edit      编辑入库单
- inbound:order:delete    删除入库单
- inbound:order:approve   审核入库单
- inbound:receive:view    查看收货任务
- inbound:receive:operate 执行收货作业
- inbound:inspect:view    查看验收任务
- inbound:inspect:operate 执行验收作业
- inbound:putaway:view    查看上架任务
- inbound:putaway:operate 执行上架作业

系统管理模块权限：
- system:user:view        查看用户列表
- system:user:create      创建用户
- system:user:edit        编辑用户
- system:user:delete      删除用户
- system:role:view        查看角色列表
- system:dict:view        查看字典列表
```

## 四、功能需求

### Story 1: 权限初始化（数据层）

**作为** 系统
**我希望** 系统启动时自动初始化权限数据
**以便** 权限校验可以正常工作

**验收标准:**
- [ ] 初始化所有菜单权限（7个模块菜单）
- [ ] 初始化所有操作权限（约80+个权限）
- [ ] 初始化角色权限关联（9个角色 × 对应权限）
- [ ] 权限数据幂等（重复执行不会产生重复数据）
- [ ] 提供SQL迁移脚本

**实现方式:**
- 创建数据库迁移脚本 `V12__init_permissions.sql`
- 包含所有权限的INSERT语句
- 包含所有角色权限关联的INSERT语句

---

### Story 2: 角色列表查看

**作为** 系统管理员
**我希望** 查看系统中所有角色
**以便** 了解角色的权限配置

### Story 9: 权限缓存优化

**作为** 系统
**我希望** 权限数据被缓存
**以便** 提高权限校验性能

**验收标准:**
- [ ] 用户权限缓存到Redis
- [ ] 缓存过期时间可配置（默认30分钟）
- [ ] 用户角色变更时清除缓存
- [ ] 用户登出时清除缓存
- [ ] 多角色权限合并并去重

**实现方式:**

```java
// 1. 权限缓存Key
String cacheKey = "user:permissions:" + userId;

// 2. 获取用户权限（带缓存）
public Set<String> getUserPermissions(Long userId) {
    // 先查缓存
    Set<String> permissions = redisTemplate.opsForSet().members(cacheKey);
    if (permissions != null && !permissions.isEmpty()) {
        return permissions;
    }

    // 查询数据库
    permissions = new HashSet<>();
    List<Role> roles = userRoleMapper.selectByUserId(userId);
    for (Role role : roles) {
        // 多角色权限取并集（自动去重）
        List<Permission> rolePermissions = permissionMapper.selectByRoleId(role.getId());
        permissions.addAll(rolePermissions.stream().map(Permission::getCode).collect(Collectors.toSet()));
    }

    // 写入缓存
    if (!permissions.isEmpty()) {
        redisTemplate.opsForSet().add(cacheKey, permissions.toArray(new String[0]));
        redisTemplate.expire(cacheKey, 30, TimeUnit.MINUTES);
    }

    return permissions;
}

// 3. 清除缓存（角色变更时调用）
public void clearUserPermissionCache(Long userId) {
    redisTemplate.delete("user:permissions:" + userId);
}

// 4. 登出时清除缓存
public void logout() {
    Long userId = SecurityUtils.getUserId();
    redisTemplate.delete("user:permissions:" + userId);
    // ... 其他登出逻辑
}
```

## 八、注意事项

### 8.1 安全注意事项

1. **权限编码不要泄露敏感信息**
   - ❌ `user:delete:admin` （泄露了管理员权限）
   - ✅ `system:user:delete`

2. **权限校验必须后端实现**
   - 前端权限控制只是UI优化
   - 所有敏感操作必须后端校验权限

3. **默认拒绝原则**
   - 没有明确授权的操作都应该被拒绝
   - 不要依赖前端的隐藏按钮

### 8.2 性能注意事项

1. **权限缓存**
   - 用户权限应该缓存，避免每次查询数据库
   - 角色变更时清除缓存

2. **批量权限查询**
   - 一次性获取用户所有权限，避免多次查询

3. **菜单权限优化**
   - 菜单权限可以存储在前端
   - 定期刷新即可，不需要每次请求都查询

### 8.3 维护注意事项

1. **权限编码规范**
   - 严格按照规范命名
   - 新增权限必须更新权限清单文档

2. **权限变更记录**
   - 记录权限变更历史
   - 便于追溯和审计

3. **角色权限文档**
   - 保持文档与实际配置一致
   - 定期核对权限矩阵

## 附录：权限数据初始化SQL示例

```sql
-- ========================================
-- 权限数据初始化脚本 (V12__init_permissions.sql)
-- ========================================

-- 1. 修改角色表，增加数据范围字段
ALTER TABLE sys_role
ADD COLUMN IF NOT EXISTS data_scope TINYINT DEFAULT 2
COMMENT '数据权限范围: 1-全部仓库 2-所属仓库';

-- 更新系统管理员数据范围
UPDATE sys_role SET data_scope = 1 WHERE code = 'SYSTEM_ADMIN';

-- 2. 插入菜单权限（幂等）
INSERT INTO sys_permission (code, name, module, type, sort_order)
SELECT 'dashboard:menu', '仪表盘菜单', 'dashboard', 'menu', 1
FROM DUAL WHERE NOT EXISTS (SELECT 1 FROM sys_permission WHERE code = 'dashboard:menu');

INSERT INTO sys_permission (code, name, module, type, sort_order)

-- 4. 插入角色权限关联（幂等）
-- 示例：系统管理员权限
INSERT INTO sys_role_permission (role_id, permission_id)
SELECT r.id, p.id FROM sys_role r, sys_permission p
WHERE r.code = 'SYSTEM_ADMIN'
AND p.code IN (
    'dashboard:menu', 'dashboard:view',
    'system:menu', 'system:user:view', 'system:user:create', 'system:user:edit', 'system:user:delete', 'system:user:resetPwd', 'system:role:view', 'system:dict:view',
    'inbound:menu', 'inbound:order:view', 'inbound:order:create' -- ... 其他权限
)
AND NOT EXISTS (SELECT 1 FROM sys_role_permission rp WHERE rp.role_id = r.id AND rp.permission_id = p.id);

-- ... （其他角色权限关联类似）
```
